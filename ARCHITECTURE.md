# Architecture

This document is the authoritative description of the
project's source/generated file boundary. It defines which
paths are human-maintained source and which are generated
output, and it tells contributors where to edit and where
not to.

## Top-level layout

    .
    ├── ARCHITECTURE.md              # this file
    ├── README.md                    # project intro, status, catalogue, build commands
    ├── package.json                 # contributor npm scripts (validate/build/check)
    ├── catalog/                     # canonical effect metadata
    │   ├── effects.json             # single source of truth for catalogue
    │   └── SCHEMA.md                # schema and conventions
    ├── effects/                     # per-category CSS and demo HTML pages
    │   ├── template.html            # canonical effect-page template
    │   ├── template.css             # shared page chrome styles
    │   └── <category>/              # one folder per category
    ├── scripts/                     # contributor Node.js tooling
    │   ├── validate-catalog.js      # metadata/implementation consistency
    │   ├── build-catalog.mjs        # regenerates index.html catalogue section
    │   └── build-readme.mjs         # regenerates README.md catalogue section
    ├── src/                         # (planned) hand-authored website source
    ├── templates/                   # (planned) page templates used by the build
    ├── dist/                        # (planned) generated static-site output
    └── .github/workflows/           # CI: runs npm run check on every PR and push

`src/`, `templates/`, and `dist/` are intentionally not
created yet; they will be introduced by later issues as
part of the build-pipeline migration. Nothing currently in
the repository will be moved or renamed.

## Source vs generated

**Source** = anything a contributor edits by hand.

| Path | Type | Notes |
| --- | --- | --- |
| `catalog/effects.json` | source | Single source of truth for category and effect metadata. Add new effects here. |
| `catalog/SCHEMA.md` | source | Documents the metadata schema. |
| `effects/template.html` | source | Canonical effect-page template. |
| `effects/template.css` | source | Shared page chrome styles. |
| `effects/<category>/<category>.css` | source | All CSS rules for a category. |
| `effects/<category>/<effect>.html` | source | One demo page per effect. |
| `scripts/*.js`, `scripts/*.mjs` | source | Contributor tooling. |
| `src/`, `templates/` | source | (planned) website source and page templates. |
| `index.html` | partial | Header, aside, footer, and main open/close are hand-written. The catalogue between `<!-- BEGIN GENERATED EFFECT CATALOG -->` and `<!-- END GENERATED EFFECT CATALOG -->` is regenerated by `npm run build`. |
| `README.md` | partial | Intro, status, layout, contribution, accessibility, and build-command sections are hand-written. The catalogue between `<!-- BEGIN GENERATED EFFECT CATALOGUE -->` and `<!-- END GENERATED EFFECT CATALOGUE -->` is regenerated by `npm run build`. |

**Generated** = any file produced by tooling.

| Path | Type | Notes |
| --- | --- | --- |
| `dist/` | generated | (planned) full static-site output. The intended destination of `npm run build` after the src/dist migration in #181/#182. |

## Editing rules

1. Edit source files; never edit generated files.
2. To add, rename, or reorder an effect or category,
   edit `catalog/effects.json`, then run `npm run build`.
3. To change the catalogue layout in `index.html` or
   `README.md`, edit the corresponding `scripts/build-*.mjs`
   template; do not hand-edit the marked sections.
4. To change anything outside the marked catalogue sections
   (page chrome, header, footer, status, contribution docs),
   edit the file directly.
5. The CI workflow `.github/workflows/catalog-check.yml`
   runs `npm run check` on every push and PR. A PR that
   changes `catalog/effects.json` without running
   `npm run build` will fail CI; a PR that hand-edits a
   marked section will also fail.

## Runtime guarantee

The published site remains plain HTML/CSS. There is no
frontend framework, bundler, or runtime JavaScript in the
output. The build pipeline exists only to keep the
catalogue in sync with the canonical metadata.
