# Pure CSS Image Hover Effects

A copy-paste library of pure-CSS image hover effects. One class on a `<div>`. No JavaScript. Works on every modern desktop browser.

**54 effects across 10 categories:** zoom, pan, 3d, filter, reveal, fade, shadow, light, overlay, composite.

[browse the catalog →](index.html) · [read the contract →](CONTRACT.md) · [metadata schema →](META_SCHEMA.md) · [browser support →](BROWSER_SUPPORT.md)

---

## Usage

Pick an effect from the [catalog](index.html). Each effect is a self-contained directory you can copy verbatim.

### Copy-paste in 3 steps

1. **Copy the markup** into your HTML:

   ```html
   <div class="hover-effect zoom-in" tabindex="0">
     <img src="your-image.jpg" alt="">
   </div>
   ```

2. **Copy the effect's CSS** from `effects/<slug>/effect.css` into your stylesheet (or `<link>` it).

3. **Include the shared base stylesheet** from `styles/base.css`. This provides the `.hover-effect` wrapper, the desktop-only guard, the reduced-motion suppression, and the focus-visible ring.

That's it. The effect activates on `:hover` and on `:focus-visible` (keyboard).

### Minimal complete example

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Demo</title>
  <link rel="stylesheet" href="styles/base.css">
  <link rel="stylesheet" href="effects/zoom-in/effect.css">
  <style>
    .hover-effect.zoom-in { width: 320px; border-radius: 8px; overflow: hidden; }
  </style>
</head>
<body>
  <div class="hover-effect zoom-in" tabindex="0">
    <img src="https://picsum.photos/600/400" alt="Demo">
  </div>
</body>
</html>
```

Open in a desktop browser. Hover or focus the image.

## What this library guarantees

Every effect in this repo satisfies the rules in [`CONTRACT.md`](CONTRACT.md):

| Rule | Where enforced |
|------|----------------|
| Pure CSS, zero JavaScript | `CONTRACT.md §1` · validated by `scripts/validate_effects.py` |
| Class on a `<div>` wrapper | `CONTRACT.md §2` |
| Works on the majority of desktop browsers | `CONTRACT.md §3` · see [`BROWSER_SUPPORT.md`](BROWSER_SUPPORT.md) |
| Respects `prefers-reduced-motion` | `CONTRACT.md §4` · handled globally in `styles/base.css` |
| Keyboard accessible via `:focus-visible` | `CONTRACT.md §5` |
| Self-contained per-effect directories | `CONTRACT.md §6` |

CI fails the build if any effect violates any rule.

## Repository layout

```
.
├── CONTRACT.md            # the rules every effect must satisfy
├── META_SCHEMA.md         # metadata schema (human-readable)
├── schemas/
│   └── meta.schema.json   # the same schema, machine-readable (Draft 2020-12)
├── BROWSER_SUPPORT.md     # baseline + feature support matrix
├── README.md              # this file
├── index.html             # the catalog (generated)
├── styles/
│   ├── base.css           # shared rules, owned by the library
│   └── catalog.css        # catalog page styling
├── scripts/
│   └── build_catalog.py   # regenerates index.html from meta.json
└── effects/
    ├── _template/         # canonical template (effect.css, index.html, meta.json)
    └── <slug>/            # one directory per effect
        ├── effect.css     # effect-specific rules
        ├── index.html     # demo + usage page
        └── meta.json      # schema-validated metadata (source of truth)
```

The single source of truth is `effects/*/meta.json`. `index.html` is regenerated by `python3 scripts/build_catalog.py`.

## Adding a new effect

1. Copy `effects/_template/` to `effects/<your-slug>/`.
2. Edit the three files:
   - `effect.css` — replace `<effect-class>` and define the hover state.
   - `index.html` — replace `<Title>`, `<slug>`, and the description.
   - `meta.json` — fill every field. Set `category` to one of the 13 enum values; `js_required` and `extra_markup` must stay `false`.
3. Run `python3 scripts/validate_effects.py`. It must pass.
4. Run `python3 scripts/build_catalog.py` to refresh the catalog.

The new effect is then visible in the catalog and reachable via the per-effect page.

---

## Mobile and tablet

Hover effects are intentionally **desktop-only** on touch devices. The shared base stylesheet suppresses all hover/focus states under `@media (hover: none)`. This is by design — touch users have no hover affordance, and the contract §3 states that mobile/tablet is out of scope.
